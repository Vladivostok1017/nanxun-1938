# 战役数据底稿

> 把三份数据源合成一份可录入的底稿，并处理一个绕不开的问题：**大部分师级兵力没有史料记载**。
> 本文不是史料考据，是数据工程。

---

## 1 三个数据源与各自的可靠度

| 源 | 内容 | 可靠度 | 用法 |
|---|---|---|---|
| **A. 战役推演视频** | 47 分钟地图动画，逐帧 OCR 提取。含各战斗的双方兵力标注、番号、指挥官、战果 | **中低**。数字来源不明，应为创作者估算；但空间与编制关系清楚 | 补缺口、做量级校验；不能当史料引用 |
| **B. 中文史料核对**（`03` 文档） | 编制树落到师+师长、派系、时间线矛盾、伤亡总数、来源分级 | **中高**。有两源交叉，冲突处并列 | 编制树与派系的**主来源** |
| **C. 公开史料补充** | 蒋介石电文、地方党史方志、台版战史转写 | **中高**（电文）／中（转写） | 时间线校验 |

**原则**：编制关系用 B，兵力量级用 A+B 交叉，时间线用 B 的建议时间线，冲突处并列不裁决。

三个源叠加后，一个事实很显眼：**同一场战斗，视频给的兵力数字和史料记载往往对不上**。这不是谁的错——1938 年的中国军队自己都搞不清报上来的数字。

## 5 核心问题：兵力数据大面积缺失

这是整个数据工作里最重要的一条，必须正面处理。

### 5.1 缺口有多大

`03` 文档明确写着：

> 除第 36 师（1 万余人）外，**几乎所有中国师的"实有兵力"均无记载**。

即使是中国军队 1938 年的师编制约 1 万—1.1 万人，实有数普遍远低，但没有逐师数据。分月伤亡也完全没有，只有总数。

### 5.2 两条错误的路

**错误一：编数字。** 给每个师填一个"看起来合理"的数。后果是玩家以为这是史实，而实际上是编的；一旦有人较真，整个项目的可信度崩掉。

**错误二：全部留空。** 会导致模拟核心无法运行——战斗解算需要兵力。

### 5.3 正确做法：把不确定性做成机制

**关键洞察：史料的不确定性，恰好对应真实战争的信息不确定性。**

1938 年的中国师长，自己也不知道手下到底有多少人。报上来的数字是估的，逃兵没统计，补充兵没到齐。如果游戏显示精确到个位的兵力，**反而不真实**。

所以：

**内部用精确值，外部显示区间。**

| 层 | 表达 |
|---|---|
| 模拟核心 | 每师一个确定的兵力值（定点数），保证确定性与可重放 |
| 数据文件 | 兵力值标 `"estimated": true` + `source` + `range`，注明是推断 |
| 玩家界面 | 显示"约八千人""兵力不足""满编"，不显示精确数字 |
| 情报系统 | 精度由侦察决定。侦察不足时，连"约八千人"都可能偏差 ±40% |

这样做的收益不止是"绕过数据缺口"：

- **真实感提升**：玩家像真实指挥官一样，在信息不完整时做决策
- **决策难度提升**：不能靠数数字赢，必须靠判断
- **数据缺口的责任转移**：不是"我们没查到"，而是"当时也没人知道"

### 5.4 具体实现

```yaml
# 数据文件
divisions:
  - id: div.74_58
    name: 第58师
    commander: 冯圣法
    parent: corps.74
    faction: central
    strength:
      value: 9200
      estimated: true          # ← 必须是 true
      range: [7000, 10500]
      basis: "按74军满编率推算，与58师伤亡数字交叉校验"
      source: "推断"
    casualties_known:
      killed_officers: 64
      killed_men: 2416
      wounded_officers: 164
      wounded_men: 3180
      missing: 435
      source: "S10"
```

界面层读取 `strength` 时走一个"情报滤镜"：根据侦察等级决定显示精度。

```rust
enum StrengthDisplay {
    Precise { value: u32 },           // 仅侦察极充分时
    Approximate { center: u32, error: u32 },  // 默认
    Qualitative(QualitativeLevel),    // 满编/充足/不足/枯竭
    Unknown,
}
```

**这条设计值得写进原则**：凡是史料不确定的地方，都用"信息不确定性"来表达，而不是用"编造的数字"来表达。这既是诚实，也是更好的游戏。

## 6 派系数据

`03` 文档已做成军级对照：中央军约 19 个军、西北军 7、川军 6、桂系 4、粤军 3、东北军 3。另有 6 个单位标 `?`。

**处理建议（来自 03 文档，我认同）**：标 `?` 的一律设为 `unaligned`（中立/未定），不要猜。因为派系判断错误会直接影响推演平衡和叙事真实性。

M2 只做三个派系（中央军、桂系、川军），其余全部 `unaligned`。这样既有派系张力，又不至于一上来就陷入考据泥潭。

## 7 对设计的三条实际影响

**第一，兵力不能做成可见的精确数字。** 这是被史料逼出来的设计，但结果更好。UI 上从"第 58 师 9,200 人"改成"第 58 师 · 兵力约八千 · 士气尚可"。

**第二，时间断面必须做 2-3 个。** 编制在 5 个月里变化很大，单一快照会出错。建议按 6 月、8 月、10 月切三个断面，切换时处理转隶与升格。

**第三，日方数据可以更简化。** 只做中方可玩，日方不需要逐师数据——用"师团 = 兵力 + 战斗力 + 补给状态 + 推进目标"的模板，再配合视频给出的兵力量级，足够驱动敌方 AI。

| 逐师实有兵力 | 需全量推断 | 按满编率 + 战役消耗曲线反推，全部标 `estimated` |
